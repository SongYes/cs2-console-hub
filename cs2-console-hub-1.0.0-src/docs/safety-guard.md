# CS2 实验操作安全指南 —— 怎么才能不"手滑"吃 VAC

> 一句话结论：**别靠小心，靠把两种环境物理隔开。**
> 实验模式（改素材 / 录 demo / 抓数据）永远带 `-insecure`；
> 想进官方竞技服，必须用不带 `-insecure` 的启动方式，并且先跑一次上锁检查。

---

## 一、先搞清楚 VAC 到底抓什么

不搞清这个，防护就会做错方向。

| 行为 | 会被 VAC 抓吗 | 说明 |
|---|---|---|
| 替换天空盒 / 模型 / 贴图 / 枪械外观 | **通常不会直接触发** | 属于客户端素材，VAC 不逐字节校验（但见下方"但是"） |
| 改 `csgo/cfg/*.cfg`、autoexec | **不会** | 配置文件是允许的 |
| 用 `-insecure` 起游戏、连本地/社区服 | **不会** | 这是 Valve 给的正规开关，专门用于非受信环境 |
| 改 `steamclient*.dll`、劫持 Steam API | **会，且是最重的一类** | 破坏平台完整性 |
| 往游戏进程注入第三方 DLL、做内存读写 | **会** | 签名扫描的经典目标 |
| 用外部工具自动瞄准 / 透视 / 反后坐 | **会** | 且是永久封禁 |
| 读取游戏内存来做数据抓取 | **不会封号，但有风险面** | 纯读取通常不触发 VAC；一旦伴随注入/写内存就危险 |

**但是**——这是关键：改素材虽然一般不直接触发 VAC，却会让你进入"非受信环境"。
一旦你在同一台机器、同一个 Steam 账号上，把"改素材"和"注入类工具"混在一起用，
VAC 判定的是**整体环境**，你就很容易被连带。

所以真正的防护目标是：**保证"进受保护服务器"这件事，只发生在确认干净的状态下。**

---

## 二、核心手法：把两种启动方式固定成两个入口

不要手动去改 Steam 的启动选项（最容易手滑的就是这一步——忘了删 `-insecure` 或忘了加）。

### 实验模式（改素材 / 录 demo / 抓数据）

Steam 启动选项固定为：

```
-insecure -condebug
```

- `-insecure`：**不会连接受 VAC 保护的服务器**。这是你的安全带。
- `-condebug`：把引擎日志写到 `game/csgo/console.log`，方便排查。

在这个模式下你随便折腾：换天空盒、刷模型、录 demo、抓 cvarlist、读内存。
**代价**：进不了官方竞技服、官匹匹配、受 VAC 保护的社区服。

### 正常模式（要打官匹 / 竞技）

启动选项清空（或只留性能类参数），**绝对不能带 `-insecure`**。

### 切换纪律

1. 切换前先跑一次上锁检查（见第三节），必须是 ✅。
2. 切换后确认一下：`-insecure` 有没有真的加上/删掉（Steam 有时不立即生效，重开 Steam 最稳）。

> 如果你希望更省事：给 CS2 建两个 Steam 快捷方式做不到（Steam 只存一份启动选项），
> 那就用一个**切换脚本**改启动选项 + 备份，别手改。本项目暂不自动改 Steam 配置，
> 因为改坏了修起来更麻烦；纪律 + 检查脚本已经足够。

## 三、进服前的上锁检查（每次必做，3 秒）

本项目带了一个检查器：先记录一次干净基线，之后每次比对。

### 首次：确认干净后记基线

```powershell
python tools\guard_check.py --baseline
```

基线会记录 854 个敏感文件（vpk / dll / exe）的大小 + 取样哈希。

### 之后：每次进服前

```powershell
python tools\guard_check.py
```

输出三种结论之一：

- ✅ **与基线一致，可以正常进服** —— 放心玩
- ⚠ **不适合进受保护服务器** —— 有文件被改过 / 多出可疑文件，先处理
- 没基线 —— 先按上面记一次

它检查的项：

1. 敏感文件与基线是否一致（**素材有没有被换过**）
2. 是否多出基线里没有的可执行文件（**有没有塞注入器**）
3. 是否少文件（被误删）
4. 是否出现不在 Valve 目录里的 dll/exe
5. 可选：游戏进程里是否挂着第三方模块（`--modules`）
6. 当前 CS2 命令行里有没有 `-insecure`

### 出问题怎么修

```powershell
# 让 Steam 把被改的文件重新下载回官方版本
Steam → 库 → Counter-Strike 2 → 属性 → 已安装文件 → 验证游戏文件的完整性
```

验证完再跑一次 `guard_check.py`，确认回到 ✅。

## 四、各类实验操作的安全做法

### 4.1 换天空盒（demo / 录制）

**为什么相对安全**：天空盒是客户端素材，而且你在本地图里换。

```cfg
// 推荐：不改任何文件，用控制台指令换
sv_skyname sky_dust
```

想试自定义天空盒：

1. **放对位置**：只需要 `.vtex_c`（编译好的材质），不要塞 `.vpk`。
   路径：`game/csgo/materials/skybox/`
2. **用不覆盖原文件的名字**：`mysky_rt.vtex_c` 之类，别叫 `sky_dust_rt.vtex_c`。
   覆盖原文件名 = 以后"验证文件完整性"时会和 Steam 打架。
3. **只在本地图实验**：`map <本地图>` → `sv_skyname mysky`。
4. **收工就删**：实验完把那几个 `.vtex_c` 删掉，然后跑 `guard_check.py` 确认回到 ✅。

⚠ **绝对不要碰** `game/core/*.vpk`、`game/csgo/pak01_*.vpk`。
往里面塞文件等于重打包官方素材，这是最容易被完整性校验抓到的做法。

### 4.2 替换枪械 / 地图模型

模型是 `.vmdl_c`，路径 `game/csgo/models/`（地图模型在 `maps/`）。
规则同上：**不覆盖官方文件名，实验完删除**。

> 想更彻底地隔离：把实验素材放进一个自己的 addon 里（CS2 的 workshop addon 机制），
> 这样官方文件一个都不动，`guard_check.py` 永远保持 ✅。这是最干净的方案。

### 4.3 抓游戏数据（比如本项目的 cvarlist 导出）

```cfg
cvarlist          // 或 condump cs2hub_full.txt
```

- 用 `condump` 落盘到 `game/csgo/`，这是**纯新增文件**，不会让检查器报警（已被加入白名单）。
- **读进程内存**（本项目的 `tools/scan_proc_memory.py`）属于**纯读取**，不改游戏内存，
  通常不触发 VAC。但请注意：
  - 一定要在 `-insecure` 下做；
  - 不要用带"写内存"能力的调试器（Cheat Engine、x64dbg 附加并修改）附到游戏进程，
    那才是真正的高危动作；
  - 抓完重启游戏再决定要不要进服。

### 4.4 Demo 录制与回放

- `record <名字>` / `stop`、`playdemo`、`demoui` 都是官方命令，安全。
- demo 文件在 `game/csgo/`，属于新增文件。
- 不要为了"改 demo 里的天空盒"去改 `pak01_*.vpk`。

## 五、开始任何实验前的 30 秒准备

```powershell
# 1. 确认现在是干净的（必须 ✅）
python tools\guard_check.py

# 2. 记一次"实验前"基线快照（可选，但强烈建议：能一键看出这次实验到底动了什么）
copy data\integrity_baseline.json data\integrity_before_experiment.json

# 3. 启动实验模式（Steam 启动选项：-insecure -condebug）
```

实验结束后：

```powershell
# 4. 看这次实验到底动了哪些文件（与实验前快照比对）
python tools\guard_check.py
```

## 六、万一已经发生：应急处置

如果你怀疑自己**在正常模式下进过官方服、而且机器上有改过的东西**：

1. **立刻退出游戏**，不要再进任何官方服务器。
2. 跑上锁检查，看清到底动了什么：
   ```powershell
   python tools\guard_check.py --modules
   ```
3. 验证游戏文件完整性（Steam → 属性 → 已安装文件）。
4. 删除所有非官方来源的 `dll / asi / exe`，尤其是注入器类工具。
5. 关掉一切外挂性质软件（哪怕只是"性能优化器""皮肤修改器"）。
6. 之后至少一段时间内，只在 `-insecure` 下玩；要打官匹，先用干净环境验证过再进。

**关于封禁的现实**：VAC 封禁是永久的、绑定账号，且不会因为"我只是换了天空盒"而自动豁免。
Valve 不会公开判定细节，所以**唯一可靠的做法就是不让受保护环境和实验环境重叠**。

## 七、本项目的安全边界（承诺）

- 本工具**只读**游戏数据：读 `data/`、读游戏目录文件、读进程内存（不写游戏内存）。
- **唯一会写入游戏目录的东西**：`game/csgo/cfg/dump_commands.cfg`、`verify_gap.cfg`（明文配置脚本）
  以及你自己执行的 `condump` 输出。这些都在检查器白名单里。
- 本工具**不会**：改 `pak01_*.vpk` / `core/*.vpk`、注入 DLL、改 `steamclient`、碰你的
  `-insecure` 设置、动 Steam 的启动选项。
- 所有对游戏目录外的东西（`data/`、`docs/`、`_dumps/`）都是普通文件读写。

| 我要做什么 | 启动选项 | 是否要检查 | 备注 |
|---|---|---|---|
| 打官匹 / 竞技 | 不带 `-insecure` | ✅ 必须先 ✅ | |
| 换天空盒 / 模型实验 | `-insecure -condebug` | 实验前后各一次 | 别碰 vpk，别覆盖官方文件名 |

| 不确定 | 先 `-insecure` | ✅ | 宁可进不去官匹，也别赌 |
